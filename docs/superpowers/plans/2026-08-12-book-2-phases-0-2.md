# Book 2 — implementation plan, phases 0-2

Spec: `docs/superpowers/specs/2026-08-12-book-2-downward-design.md`.

Scope is **phases 0, 1 and 2 only** (owner ruling). Phase 2 answers the question the whole book
rests on; phases 3+ are not planned because they may never happen. Everything here is gated —
owner playtests it on a phone against the live URL via the dev toggle.

| Phase | What | Player-visible | Ships as |
|---|---|---|---|
| 0 | `meta.dev` + 7-tap toggle + DEV pill | none | patch |
| 1 | `BOOKS` + `CHAPTER_ORDER` alias + `nextChapter` null fix | none | patch |
| 2 | The Shelf, mechanic only, wearing the pond's clothes | gated | minor |

**Phase 2 is a decision gate.** If chasing a bar to fuel a skill is a chore, stop — nothing
downstream has been built.

---

## Architectural rules

Two rules carry the whole design. Everything below follows from them.

### R1 — `meta.dev` must never reach sim.js

sim.js knows nothing about visibility. It reads `CHAPTERS[run.chapter]` and plays whatever it is
handed. All gating lives in config.js helpers and ui.js.

Two consequences, both load-bearing:
- The dev flag **structurally cannot change gameplay**, so what is tested behind the gate is exactly
  what ships.
- sim stays headless-testable, which is how the entire charge system gets covered with no browser.

If a `meta.dev` check ever appears in sim.js, the design has gone wrong — go back to the caller.

### R2 — the charge system is a chapter-gated no-op

`stepCharge` early-outs unless `CHAPTERS[run.chapter].resource` exists, exactly as `stepCurrents`,
`streamTraps` and `stepGravityWells` do on their signatures. No feature flag anywhere in sim.

This is why the mechanic can live in `main` from day one: chapters that do not declare `resource`
are bit-for-bit unaffected, and the existing suite proves it.

## Phase 0 — the dev toggle

No player-visible change. Nothing else can hide without this.

**`src/state.js`**
- `loadMeta` migration: `m.dev = m.dev === true` (next to `m.lang ??= 'en'`). Coerced, not `??=`,
  so a tampered value cannot be truthy-but-not-boolean.
- Fresh meta literal: `dev: false`.

**`src/ui.js`**
- `data-act="dev-tap-wip"` on the title `.coins-badge` (ui.js:636).
- New `case 'dev-tap-wip'` in the `data-act` switch, reusing `DEV_TAPS_TO_OPEN` (7) and
  `DEV_TAP_WINDOW_MS` (1000) and its own counter pair — **not** the in-run counter's, so a title tap
  can never partially arm the in-run menu.
- On the 7th tap: `hooks.onDev?.(!meta.dev)`, `playSfx('buy')`, `renderTitle()`.
- A **DEV pill** on the title whenever `meta.dev`. Without it you cannot tell whether a chapter on
  screen is shipped or WIP, which is the real danger of a hidden flag.

**`src/main.js`**
- `onDev(on) { meta.dev = on; saveMeta(meta); playSfx('click') }` — mirrors `onLang`.

**Tests** (`test/sim-test.js`): `meta.dev` survives a round-trip; absent, `null` and `'yes'` all
load as `false`.

**Done when:** seven taps on the title coin badge toggles a visible DEV pill, and it survives a
reload.

## Phase 1 — BOOKS

No player-visible change. This is also a live bug fix.

### The key move: `CHAPTER_ORDER` becomes a derived alias

```js
export const BOOKS = {
  book1:    { name: 'The Anomaly', chapters: [...the current seven], hidden: ['blank'] },
  downward: { name: 'Downward', chapters: ['shelf'], hidden: [], wip: true },
}
export const CHAPTER_ORDER = BOOKS.book1.chapters
```

Every one of the ~15 `src/` and ~40 `test/` read sites keeps working **untouched**, and keeps
doing the right thing: `slotSummary` still reports Book 1 as "7 of 7", `dailyChapter` still draws
only from shipped chapters. The refactor is additive, so it cannot break Book 1 by omission.

**`src/config.js`**
- `BOOKS` + the alias above.
- `bookOf(chapterId)` → the book id, or `null`.
- `nextChapter(id)` — returns `'body'` for any id outside the order, because `indexOf` is `-1` and
  `-1 + 1` indexes element 0. Verified: `nextChapter('blank') === 'body'`. **Latent, not live** — an
  earlier draft of this plan called it a live bug twice, which was an overstatement. Both call sites
  are inert: `ui.js:76` is only ever fed ids already filtered through `CHAPTER_ORDER` (ui.js:75),
  and `main.js:399` is followed by an `unlocked` check that `body` always passes. Fix it anyway —
  look up the id's own book, return `null` past that book's end and for an unknown id — because the
  new book is what would make it reachable.
- `resolveChapterId(id)` — **leave it alone.** An earlier draft made it dev-aware, which was wrong:
  `createRun` calls it a *second* time (`state.js:1283`) and `main.js:46` passes no `dev`, so every
  dev-toggled Shelf run would have silently become a Body run — no throw, no warning, and `endRun`
  crediting body's ledger. That is the documented `createRun(meta, 'undergrowth', 3)` trap rebuilt
  one layer up, and it would have shipped green, because the one existing test that would catch it
  (`test/sim-test.js:11143`) iterates `CHAPTER_ORDER`, which by design never contains `shelf`.
- Instead the visibility gate lives in **exactly one new function**, `playableChapterId(meta)`, used
  by the play path only. `resolveChapterId` stays a pure "is this a real chapter" check, so every
  sim-adjacent caller keeps passing a legitimately-selected `shelf` straight through. This is R1: a
  gate in a shared helper leaks into callers that know nothing about visibility.

**`src/state.js`**
- `ensureChapterMeta` loop covers every book's chapters, not just `CHAPTER_ORDER`. Creating entries
  for WIP chapters is deliberate and harmless: toggling dev then needs no migration.
- `slotSummary` unchanged — it must keep counting Book 1 only.

**`src/main.js` / `src/ui.js` — a selection path, which is NOT optional**

An earlier draft left "the book pager" out of scope. That was fatal: **nothing could have selected
The Shelf**, so phase 2 could never have reached its own decision gate. Two independent gates, both
verified:
- `titleChapterList` (ui.js:74-88) builds the carousel from `CHAPTER_ORDER.filter(unlocked)` plus a
  hand-written `base.push('blank')`. Keeping `CHAPTER_ORDER` as `BOOKS.book1.chapters` — the
  headline move above — is exactly what makes `shelf` unlistable.
- `onChapter` (main.js:236) refuses any id where `ensureChapterMeta(meta, id).unlocked` is false,
  and `ensureChapterMeta` defaults `unlocked` to `id === 'body'` (state.js:202) — so this plan's own
  "creating entries for WIP chapters is harmless" creates `shelf: { unlocked: false }` and then
  bounces it.

The minimum that unblocks phase 2 — a full pager can wait:
- `titleChapterList` appends a `wip` book's chapters **when `meta.dev`**, the same explicit-append
  idiom already used for `blank`.
- `onChapter` accepts a WIP id when `meta.dev`.
- `playableChapterId(meta)` — the single dev-aware gate — is what Play reads.

**Tests** — 1-3 catch the leak, 4-5 catch the two ways this plan's own earlier draft broke:
1. `nextChapter` returns `null`, not `'body'`, past a book's end and for an unknown id (covers the
   existing `'blank'` case).
2. No `wip` chapter id is reachable from `CHAPTER_ORDER`, from `dailyChapter` over a year of date
   keys, or from `nextChapter` on any shipped chapter.
3. With `dev: false` and `meta.chapter` pointing at a WIP id, `playableChapterId` returns a shipped
   one.
4. **With `dev: true`, a WIP id survives the whole path**: `playableChapterId` returns it AND
   `createRun(meta, { chapter: 'shelf' }).chapter === 'shelf'`. This is the assertion that would
   have caught the silent downgrade to Body — note it must name the WIP id explicitly, because
   every existing test of this shape iterates `CHAPTER_ORDER`, which never contains it.
5. **With `dev: true`, `titleChapterList` contains the WIP id, and `onChapter` accepts it.** Without
   this, phase 2 is unreachable and every other test still passes.

**Done when:** the suite passes with three new assertions, and `git diff` shows no change to any
existing `CHAPTER_ORDER` call site.

## Phase 2 — The Shelf, mechanic only

The crux slice. **No new art.** `CHAPTERS[id].render` is documented as render-only with zero sim
effect, and rosters map to base archetypes — so The Shelf borrows the pond's render block and roster
wholesale. What is under test is the mechanic, and this repo's cost lives in the art tail (beyond's
13-release debugging run was entirely render; skies carried 849 lines of art spec against 209 for
its arsenal). Draw nothing until the mechanic earns it.

### 2a — config.js

`CHAPTERS.shelf`: pond's `render` block copied verbatim, pond's roster (`amoeba`, `tadpole`,
`tardigrade`), pond's weapon pool (`flagella` starter, `mines`, `bloom`), and
`balance.maxAliveMul` between `body`'s 0.45 and `pond`'s 0.60 — it is Book 2's onboarding chapter,
so it sits at the bottom of its own ladder, not partway up Book 1's. Plus:

```js
resource: { name: 'Light', drain: 0.5, refill: 15, max: 100 },
signature: { type: 'shafts', cell: …, chance: …, r: …, minDist: …, driftAmp: …, driftHz: … },
```

New constants: `PULSE_CHARGE_COST`, `PULSE_RADIUS_AT_FULL`, `PULSE_FORCE_AT_FULL`. The shipped
`REPULSE_*` values stay as the **floor** — an empty bar leaves the known-good v5.21 shove, so there
is no spiral where having no charge prevents you from earning charge.

Also add `shelf` to `MUTATORS.sticky.exclude` (it already excludes `beyond` and `pond`): a flat
−15% player speed in a chapter built on travel is an unstated tax.

### 2b — state.js

`createRun`: `charge: CHAPTERS[chapter].resource?.max ?? 0`, `shafts: []`, plus the
`_shaftCellI/_shaftCellJ` cursor. Update the run-shape doc block (state.js:438-1115) — it is the
authoritative field list and going stale is how the next person gets it wrong.

### 2c — sim.js

**`stepRepulse`** — replace `if (!CHAPTERS[run.chapter].lane) return` with a check that the chapter
declares either `lane` **or** `resource`. Spending charge scales radius and force above the shipped
floor. It still deals **no damage**: `REPULSE_CD`'s config block documents why, and that reason
should be read before it is ever changed.

**The event is a second site and it will lie if you miss it.** sim.js:1103 pushes
`{ type: 'repulse', …, r: REPULSE_RADIUS }` — the *constant* — and render.js:11533 draws both rings
at `e.r`, under a comment stating the radius is pushed rather than fixed because "a burst that lies
about its reach makes the cooldown feel arbitrary". Push the **scaled** radius, or a charge-amplified
pulse draws the 340px floor ring around a much larger shove.

**`stepCharge(run, dt)`** — early-out on `resource` (R2). Passive drain; refill while inside a
shaft; clamp to `[0, max]`. Insert next to `stepCurrents` in the step order.

**`streamShafts(run)`** — a direct copy of `streamEddies` (sim.js:2755), which is itself a
documented copy of `streamObstacles`. Four details that fail silently if missed:
- **Its own hash salts.** Obstacles use 0-4, eddies 11-14, traps 15-17. Shafts take **20-24**, so a
  shaft's roll can never collide with another streamer's at the same cell.
- **Its own cell cursor** (`_shaftCellI/_shaftCellJ`), independent of the other three.
- **Gated on `run._obstacleSeed != null`**, like the others.
- **Zero `Math.random()` at step time** — the hard rule all three streamers state explicitly.

**`stepShafts(run, dt)` — a SEPARATE function, and the reason is a trap.** `streamShafts` decides
existence only; `stepShafts` moves them. A "direct copy of `streamEddies`" structurally cannot make
anything drift: it early-returns at `sim.js:2765` (`if (ci === run._eddyCellI && cj === run._eddyCellJ) return`)
whenever the player has not crossed a cell boundary, so position is computed **once per
materialization and never again**. An earlier draft of this plan specified the copy and the drift
and gave the drift no per-frame home — shafts would have been static except at cell crossings, and
the "chase a moving light" fantasy the entire phase gate exists to judge would never have happened.
Render would have faithfully drawn the frozen field (`updateEddies` re-places from `list[i]` every
frame), so nothing would have looked broken.

**Drift stores no state and consumes no RNG:**
`x = cellCentre + sin(run._realTime * driftHz + phase) * driftAmp`, `phase` from the cell hash.

- **`run._realTime`, NOT `run.time`.** Under the Time Debt anomaly `run.time += dt * TIME_DEBT_MUL`
  (sim.js:197, `TIME_DEBT_MUL = 1.5`), and `timeDebt` has `chapter: null`, so it rolls in The Shelf.
  Deriving drift from `run.time` would make peak speed `driftAmp × driftHz × 1.5` and breach the
  ceiling below for any tune above 66.7 px/s. `run._realTime` (sim.js:205) exists precisely to be
  "a unit that means the same thing in all runs".
- Peak speed `driftAmp × driftHz` **must land between 33 px/s** (the joystick's minimum non-zero
  speed: `DEADZONE 0.15 × baseSpeed 220`, a hard cut not a rescale) **and 100 px/s**
  (`KITE_MIN_SPEED` — above it `stepStragglers` can recycle the horde into your heading; it also
  requires enemies to be beyond `KITE_DROP_MUL × spawnD` behind, so "continuously" overstates it).
- **`driftAmp` should stay under ~20px** unless the cell size is raised with it. Jitter slack is
  `cs/2 - r - 20` (sim.js:2783), so a larger amplitude lets a shaft's collider cross into a
  neighbouring cell and overlap that cell's own shaft. This is a density artifact, not a correctness
  break — the cell bookkeeping itself is safe, because `live` is keyed on `_cell` (sim.js:2772),
  which drift never changes, so a drifted shaft can neither duplicate nor be re-rolled.

**Refill-by-kill** also lands here — it needs no map object, and it is the one refill geometry that
asks for no verb the player lacks.

### 2d — ui.js / render.js

- HUD rail: reuse the `.chaos-vrail` markup and CSS shipped in v7.13/v7.14, cached like
  `chaosShown/chaosSecs` — the per-frame `textContent` write is the expensive half.
- The skill button already unhides on `lane`; extend that to `resource`. The gate is at
  **ui.js:1099** (`const laneChapter = CHAPTERS[run.chapter].lane === true`) — an earlier draft
  cited 1085, which is inside the rampage-bar block. Also retitle: ui.js:1020 hardcodes
  `aria-label="Repulse"` with a lane-flavoured `☉`.
- `updateShafts` in render.js, modelled on `updateEddies` (render.js:7771) — decals, not a rig, so
  it does **not** touch `reset()`'s flat-pool list.
- **`BIOMES` needs a `shelf` entry, so "no new art" is not literally true — it is one line.**
  `BIOMES` is a **render.js-local** table keyed by chapter id (render.js:6803), *not* part of
  `CHAPTERS[id].render`, and it falls back to `BIOMES.body` (render.js:12995). Without an entry The
  Shelf draws the **body's** floor scatter — villi, vesicles, platelets — under pond's teal tint.
  Add `shelf: BIOME_POND`. (The fallback is deliberate, per its own comment, so this fails ugly
  rather than throwing.)

**Correction to the spec:** it states `CHAPTERS[id].render` is "render-only with zero sim effect",
echoing CLAUDE.md. That is false — `render.districts` is read by sim (`sim.js:2617`,
`perKindRadius`) and by `createRun` (`state.js:1465`, `_districtSeed`). Harmless for a pond copy,
since pond declares no `districts`, but it is not the guarantee to lean on.

### 2e — scripts

`scripts/weapon-census.mjs` needs a **charge column**. It diffs enemy `hp` per step, so a
pulse-amplifying bar moves numbers the harness currently attributes to the weapon. Until that
column exists, no Book 2 balance claim is quotable — and per CLAUDE.md the census may only ever be
compared within one invocation.

### Tests

Headless, no browser — all of this is Pixi-free:
- Charge drains at the configured rate, refills in a shaft, clamps at both ends.
- **A shaft's position actually changes between two frames with no cell crossing.** This is the
  assertion that fails if `stepShafts` is missing and the streamer alone is relied on — the bug that
  would otherwise be invisible, since the field looks correct in every still frame.
- Drift is independent of the Time Debt anomaly: same positions with `timeDebt` on and off at equal
  `_realTime`.
- **A chapter with no `resource` is bit-for-bit unaffected** — same kills, same HP, same charge
  untouched. This is R2's guard and the reason the mechanic can sit in `main`.
- An empty bar still fires the shipped-strength pulse (no spiral).
- Shaft streaming is deterministic: same seed and cell → same shaft, and no `Math.random()` is
  consumed at step time.
- Peak drift speed sits inside 33-100 px/s for the shipped config.
- **Mutation-prove each one.** A test asserting a timer moved passes with the feature deleted.

### Done when

The Shelf is playable end-to-end on a phone behind the dev toggle: the bar drains, kills and shafts
refill it, the Pulse amplifies with charge, and an empty bar still shoves. Then it gets played, and
phase 3 is a decision — not a foregone conclusion.

## Deliberately not in scope

Phases 3+ (The Shelf's own art, roster, Photophore, the Basker; Twilight; Wrecks; Crust), the
`school` flag (needs a real boids pass — `resolveSeparationPair` early-outs at 20.8px for two
drones, so it is not the sign-flip the spec's first draft claimed), `ambush`, and Book 2's shop
cards. None of it should be built before phase 2 is judged.

**The book pager was moved INTO scope** — see phase 1. Not the full pager, but a dev-gated append
to the existing carousel plus an `onChapter` that accepts a WIP id. Leaving selection out meant
phase 2 shipped a chapter with no way to reach it.

## Risks

- **The gate is only safe if it is actually played behind.** `src/sync.js` — 163 lines, specced
  across 2,128, Worker deployed — has zero importers in `src/`. Work that does not have to face a
  player stops moving.
- **The Shelf must serve two audiences at once**: a 0-card newcomer and an 8-card Book 1 veteran,
  because the coin purse is shared. `body` only ever had to do the first, and took five re-tunes.
- **Borrowed clothes can become permanent.** The pond's render block is a stand-in; say so in the
  commit, and in any report, every time.
