# v6.3.1 — The Blank hits back (end-boss difficulty pass)

> Owner feedback (2026-08-02): "The end boss is too easy, waves should be twice as big, and boss
> should have 4x more hp, and first phase should move faster. Also add more telegraph or attack
> patterns for difficulty 2 and 3. Difficulty 3 should be very hard because you should have every
> permanent upgrade unlocked."
>
> Design ran through the standing three-critic adversarial panel (fun / gameplay / bugs) on
> 2026-08-02. Panel-forced decisions are marked [panel] below with the finding that forced them.

**Goal:** one release commit `v6.3.1: …` making The Blank a real final exam: doubled waves, 4×
boss HP with a desperation arc in every phase, a faster phase 1 that still honors the
fleeing-works contract, and two new hidden difficulty-ladder modifiers (Cross-Reactivity at d2+,
Affinity Maturation at d3) built entirely from existing machinery (bombs / enemyShots / strips).

## Global constraints (same as every slice)

- Module boundaries per CLAUDE.md: balance numbers ONLY in config.js; sim.js pure (no
  Pixi/DOM/localStorage); render.js never mutates `run`.
- English strings ARE the fr.js keys — every new MUTATORS name/desc gets a fr.js entry in the
  same commit.
- New tests append at the END of test/sim-test.js (seeded mulberry32 RNG order — never insert
  scenarios mid-file). Tests opt into the ladder by passing `mutators:` explicitly to createRun
  (main.js is what sources them from `CHAPTERS.blank.modsByDifficulty` in real play).
- state.js doc block (lines ~150–530) and the stepBossScript header comment must be updated when
  behavior they describe changes.
- `npm test` green before the commit. No Claude signature on commits. Commit subject:
  `v6.3.1: <one plain sentence>`.
- No new `Math.random()` draws in seeded-sensitive paths (the new reads are deterministic
  atan2/slice work; the only Math.random already in P2's node placement stays untouched).

// v6.3.1 difficulty-ladder patterns. crossReactive (d2+): each phase borrows a neighboring
// phase's read — P1 fires P2's homing shot, P2 detonates a spread trail read (P1's), P3 detonates
// a short trail echo. Borrowed reads sample every XREACT_STRIDE-th trail point [panel/fun: a
// stationary player — P2's own correct play — must get a spread field, not a stacked blast].
export const BLANK_XREACT_READ1_MUL = 1.5 // P2's borrowed-read cadence, × BLANK_READ1_T

export const BLANK_READ1_K_MATURE = 16    // full-read points at d3 (not the whole 26-buffer:

export const BLANK_NODE_MAX_MATURE = 4    // P2 node cap at d3 (slow table unchanged — floor stays 0.5:

export const BLANK_BAND_ANGLES = [0, Math.PI / 2]                                    // P3 cross
export const BLANK_BAND_ANGLES_MATURE = [0, Math.PI / 4, Math.PI / 2, 3 * Math.PI / 4] // d3: 8-arm star
export const BLANK_READ3_DESPERATE_MUL = 0.8 // [panel/gameplay] the cross keeps a MILDER desperation than the

                                             // permanently live at once — undodgeable geometry, not difficulty

## 2. sim.js — stepBossScript and friends

Import the new constants. Then:

**a) stepStandoff — catch-up cap.** Replace the chase branch:

```js
if (d > BLANK_STANDOFF_MAX) {
  // Past CATCHUP_D the boss pursues, but never faster than BLANK_CATCHUP_MAX: fleeing always
  // works (config's contract) — P1's 120 base would otherwise outrun every build at ×2.8.
  const spd2 = d > BLANK_STANDOFF_CATCHUP_D ? Math.min(spd * BLANK_STANDOFF_CATCHUP_MUL, BLANK_CATCHUP_MAX) : spd
  e.x += (dx / d) * spd2 * dt
  e.y += (dy / d) * spd2 * dt
}
```

**b) spawnBlankEnemy — blank cap.** `if (!essential && run.enemies.length >= BLANK_MAX_ALIVE) return null`
(replaces the MAX_ALIVE read; keep the comment explaining why the blank gets its own cap).

**e) Phase-advance on a non-final boss kill** (the `else` branch that banks levels): force-spend

**f) Desperation fight-wide.** After the `run.bossBar = ...` line, compute once:

```js
const desperate = boss.hp < boss.maxHP * BLANK_DESPERATE_FRAC

```

Delete P3's local `desperate` const. Apply `dmul` to every timer re-arm: P1's read
(`BLANK_READ1_T * accel * dmul`), P2's node + shot timers, P3's fan timer (already had it), and
P3's cross timer uses `(desperate ? BLANK_READ3_DESPERATE_MUL : 1)` instead of the shared mul.

**g) Shared trail-detonation helper** (module-level, near stepBossScript):

```js
// Detonate k points of the player's trail as staggered telegraph bombs (oldest first). Borrowed
// (cross-reactive) reads pass stride > 1: every stride-th sample, so a stationary player yields
// a spread field, not a stacked blast. Stagger scales with accel like the base fuse does.
function detonateTrail(run, k, stride, accel) {
  const src = stride > 1 ? run.trail.filter((_, i) => i % stride === 0) : run.trail
  const pts = src.slice(-k)
  for (let i = 0; i < pts.length; i++) {
    const fuse = BLANK_READ1_FUSE * accel + i * BLANK_READ1_STAGGER * accel
    run.bombs.push({ x: pts[i].x, y: pts[i].y, radius: BLANK_READ1_R, fuse, duration: fuse, dmg: BLANK_READ1_DMG, src: 'trail' })
  }
}
```

P1's existing inline read becomes `detonateTrail(run, mature ? BLANK_READ1_K_MATURE : BLANK_READ1_K, 1, accel)`
(note: stagger × accel is a change — [panel/bugs] the un-scaled stagger made mature volleys
overlap their own cadence).

## 5. test/sim-test.js — Run LL (append at END, style of Run FF)

Construct blank runs with explicit mutators, e.g.
`createRun(makeMeta(), { chapter: 'blank', difficulty: 2, mutators: ['accelResponse', 'crossReactive'] })`
and stage-jump via `Object.assign(run.script, { stage: N, waveIdx: 0, waveT: 0, spawned: false, bossId: null })`.
Give the player 1e6 hp. Import the new constants.

- **LL.a (P1 borrowed shot):** d2 mutators, stage 1, idle past `BLANK_SHOT_T × BLANK_ACCEL_MUL + 0.5s`
  → `run.enemyShots.length > 0` with `turnRate === BLANK_SHOT_TURN`. Control: same at difficulty 1
  (no mutators) → no enemyShots in the same window.
- **LL.b (P2 borrowed read + node cleanup):** d2, stage 3, move the player in a slow circle
  (vary input) for `BLANK_READ1_T × 1.5 × BLANK_ACCEL_MUL + 2s` → `run.bombs.some(b => b.src === 'trail')`.
  Control at d1: none during P2. Then: with a live bindnode, hard-kill the P2 boss
  (`boss.hp = 1`, weapons on) → within 1s of the boss's death no live bindnode remains.
- **LL.c (P3 star + fan + echo):** stage 5 at d3 mutators
  (`['accelResponse','crossReactive','immuneMemory','affinityMature']`): after one cross read,
  count strips pushed in that read == `BLANK_BAND_ANGLES_MATURE.length` (4); a fan volley pushes
  `BLANK_FAN_N_MATURE` (5) shots; trail-echo bombs appear (≤ `BLANK_XREACT_READ3_K` per read).
  Control at d2 mutators: strips per read == 2, fan == `BLANK_FAN_N` (3).
- **LL.d (mature P1 read K):** d3 mutators, stage 1, walk long enough to fill the trail
  (> `BLANK_TRAIL_MAX × BLANK_TRAIL_DT`s), then catch one read: bombs pushed in that read ==
  `BLANK_READ1_K_MATURE` (16). At d1: == `BLANK_READ1_K` (8).
- **LL.e (speed/HP pins + catch-up cap):** stage 1 spawn → `boss.speed === BLANK_BOSS_SPEED_P1`
  and `boss.maxHP === BLANK_BOSS_HP[0]` (d1, enemyHpMul 1). Stage 3 spawn → `BLANK_BOSS_SPEED`.
  Teleport the P1 boss 2000px away, step 1s of frames with idle input: displacement ≤
  `BLANK_CATCHUP_MAX × 1s + slack(5px)`, and > `BLANK_BOSS_SPEED_P1 × 1s` (the cap engaged, i.e.
  it pursued faster than base but under the ceiling).
- **LL.f (fight-wide desperation):** d1, stage 1: set `boss.hp = boss.maxHP * 0.1`; measure the
  gap between two consecutive trail-read volleys (frames where bombs.length jumps) ≈
  `BLANK_READ1_T × BLANK_DESPERATE_MUL` (±2 frames), vs ≈ `BLANK_READ1_T` at full hp.
- **LL.g (residue widening + variant):** d3 mutators, kill a recruit-spawned (non-`_wave`) enemy
  → a strip with `look === 'erase'` and `variant === 'residue'` appears at the corpse. At d1
  (no immuneMemory): none. Also assert P3's cross strips have NO variant.
- **LL.h (wave ×2 flows + blank cap):** `BLANK_SCRIPT[0].waves[0].n === 32` sanity pin; then with
  `run.enemies` padded to `BLANK_MAX_ALIVE - 1` dummy entries, a wave spawn still adds 1 and stops
