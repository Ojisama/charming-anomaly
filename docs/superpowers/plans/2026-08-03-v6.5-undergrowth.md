# v6.5 "The hunt" (undergrowth) Implementation Plan

> **For agentic workers:** executed task-by-task by sequential subagents; the session lead
> reviews each diff, runs probes/browser verification, and ships. Steps use checkbox syntax.

**Goal:** Kill the "signature is dead 15 seconds in" defect — the snap-trap field streams
everywhere, all run — and make the chapter's predators interact with it (cats slam traps on
landing, rats dart, claws hit harder near traps, leaves fall).

**Architecture:** trap placement moves from a one-shot origin scatter (state.js `generateTraps`)
into sim.js's deterministic cell-hash streaming (the `streamEddies` idiom, salts 15/16/17);
sprung state survives streaming via a `run._trapRearm` ledger (cell → absolute re-arm time).
Revised 2026-08-03 after the standing three-critic adversarial panel (fun / balance-math /
bugs); every decision that reverses the pre-panel draft notes the finding that forced it.

**Tech stack:** vanilla JS, no new deps. Module boundaries hold: balance numbers in config.js;
sim.js pure; render.js reads `run`, never mutates.

## Global constraints

- ZERO `Math.random()` at stream/step time (the AA.c scar) — placement is pure hash of
  (cell, `run._obstacleSeed`, salt).
- test/sim-test.js shares ONE seeded mulberry32 stream. Deleting `generateTraps`' seeded draws
  SHIFTS the stream for every scenario after line ~1188 (bugs finding 3) — Task 1 repairs this
  with the established `Math.random = mulberry32(20260714)` reseed-checkpoint idiom, never by
  weakening assertions.
- Undergrowth keeps NO `balance` block (it and beyond are the suite's balance-free isolation
  chapters — Run N depends on that).
- i18n: every new player-visible string lands in fr.js the same commit, French reviewed as
  French.
- One release commit `v6.5.0: …` on top; this plan doc rides beneath it as `chore: …` (never
  leave a chore as main's tip).

### Task 5: enemy separation — no more 100% stacks (owner directive 2026-08-03, ships as its own release)

**Files:** Modify: `src/sim.js`, `src/config.js`, `test/sim-test.js` (append).

- [ ] **config.js** — new constants next to the other enemy-movement tuning:
  `export const ENEMY_SEP_FRAC = 0.4` (two enemies may overlap until their centers are closer
  than this fraction of their combined radii; 0 would be full body-blocking, which is NOT
  wanted. The directive said "80% stack" → 0.2; the owner's live follow-up after seeing it —
  "Even less clustered, like 60% overlap" — set 0.4),
  `export const ENEMY_SEP_RESOLVE = 1` (fraction of the intrusion resolved per frame. The
  first draft's soft 0.5 LOST to convergence pressure: enemies seeking the player's exact
  point close faster per frame than a half-resolve pushes out, so a blank probe knot
  equilibrated at sub-pixel spread — full snap, stepObstacles' own idiom, verified live),
  `export const ENEMY_SEP_CELL = 64` (spatial-hash cell px; min separation stays well under
  64, so single-neighborhood search can never miss a pair).
- [ ] **sim.js** — new `stepEnemySeparation(run)` called immediately BEFORE `stepObstacles(run)`
  (terrain snaps last and wins). Build a Map cellKey → array of enemy indices (module-scope
  reusable Map, cleared per call — no per-frame Map churn); skip `_dead`,
  `_phaseSolid === false` ghosts, `rosterId === 'bindnode'`, and the blank boss (find its
  marker in spawnBlankEnemy — the essential/boss entity must never be shoved off its scripted
  phase movement; exclude by whatever field marks it, and comment which). For each enemy, pair
  against enemies in its own + forward neighbor cells (each pair once); for a pair with
  `distSq < minSep²` where `minSep = ENEMY_SEP_FRAC * (a.radius + b.radius)`: push each apart
  by `(minSep - d) / 2 * ENEMY_SEP_RESOLVE` along the unit delta. Exactly-coincident pair
